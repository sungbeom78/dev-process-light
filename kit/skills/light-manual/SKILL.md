# light-manual — 사용설명서

이 사이트를 **쓰는 사람**(나중의 나, 가족, 친구)이 설명서만 보고 따라 할 수 있게 한다.
설명서는 프로그램 폴더 안 `manual/` 에 두고, 코드와 **같은 저장**에 넣는다.

## 언제 만들고 고치나
작업 카드(light-start)의 `설명서:` 줄에 미리 정하고, 저장 전에 다시 확인한다.

| 이번 작업 | 설명서 | 할 일 |
|---|---|---|
| 처음 만듦 (첫 기능 / 새 사이트) | **새로 만듦** | `manual/README.md` + 기능 장 |
| 새 기능 추가 | **장 추가** | `manual/<기능>.md` + 목차의 기능 목록 + 바뀐 점 |
| 화면 흐름·사용 방법 변경 (버튼 위치, 입력 방법, 메뉴, 저장 위치가 바뀜) | **고침** | 그 장의 바뀐 단계 + 바뀐 점 |
| 버그 수정(사용법 같음), 정리, 색·글꼴만 바꿈 | **해당 없음** | 카드에 이유 한 줄 (예: "색만 바뀜") |

버그 수정이라도 사용자가 하는 행동이 바뀌면 "고침"이다.

## 만드는 법
폴더가 없으면 아래 틀로 만든다. 파일 이름은 기능 지도(`dev-notes/FEATURES.md`)의 기능과 맞춘 영문, 제목은 화면에 보이는 말.

`manual/README.md` (목차)
```
# <사이트 이름> 사용설명서

<무엇을 하는 사이트인지 한두 문장>

## 시작하기
1. <여는 방법: 파일 이름이나 주소>
2. <처음 화면에서 무엇이 보이는지>

## 기능 목록
- [메모](memo.md) -- 짧은 메모를 적고 지웁니다

## 바뀐 점
- 2026-10-08 할 일 목록 추가        ← 최신이 위, 날짜 + 무엇이 바뀌었나
```

`manual/<기능>.md` (기능 장)
```
# 할 일

해야 할 일을 적고, 끝나면 체크합니다.

## 따라 하기
1. 위쪽 [할 일] 탭을 누릅니다.
2. 입력 칸에 할 일을 적고 Enter 를 누릅니다. 목록 맨 위에 추가됩니다.
3. 끝난 일의 네모 칸을 누릅니다. 글자에 줄이 그어집니다.

## 알아 두면 좋은 점
- × 를 누르면 바로 지워지고 되돌릴 수 없습니다.

## 데이터는 어디에
- 이 컴퓨터의 브라우저에 저장됩니다. 다른 기기에서는 보이지 않습니다.
```

쓰는 원칙
- 버튼·메뉴는 **화면에 보이는 글자 그대로** (`[추가]`, `[할 일]` 탭). 코드 이름(`todo-input`)은 쓰지 않는다.
- **한 단계에 한 동작**, 단계 뒤에 **무엇이 보이는지**까지.
- 전문 용어는 쓰지 않거나 처음에 한 줄로 푼다. 지우면 되돌릴 수 없는 것은 미리 알린다.
- 고칠 때는 바뀐 단계만 고친다. 장을 통째로 다시 쓰지 않는다.
- 화면 그림은 브라우저 도구가 있을 때만 `manual/images/` 에 넣는다. 없으면 글로만 쓴다.

## 확인 (light-check 와 함께)
1. 바뀐 장의 **따라 하기를 실제로 그대로 해 본다**. 설명과 화면이 다르면 코드나 설명서를 고친다.
2. 목차의 기능 목록에 모든 장이 연결돼 있고, 링크·그림이 실제 파일을 가리키는지 본다.
3. 기능 지도의 `설명서` 칸에 장 파일을 적는다 (예전 기능 지도에 칸이 없으면 표에 칸을 더한다).

## 저장 후 채팅에 보여 주기
저장(light-save)이 끝나면 **요약하지 말고** 설명서를 그대로 채팅에 붙인다.
- 새로 만들었으면: `README.md` 와 모든 장
- 고쳤으면: 바뀐 장과 목차의 "바뀐 점"
- 맨 끝에 한 줄: `저장 위치: manual/README.md` (파일을 보낼 수 있는 환경이면 파일도 함께 보낸다)

사용자가 언제든 "사용설명서 보여 줘"라고 하면 목차를 보여 주고, "○○ 설명 보여 줘"라고 하면 그 장을 보여 준다.

## 하지 않는 것
- 확인하지 않은 단계를 설명서에 쓰기
- 개발자용 내용(파일 구조, 함수)을 설명서에 쓰기 -- 그건 `dev-notes/` 에 있다
- 설명서 없이 새 기능을 "기능:" 으로 저장하기
