# light-save — 저장하기

## 언제
- `light-check` 가 끝나고 사용자가 확인했을 때
- 하루 작업을 마칠 때 (만드는 중이라도 "중간 저장"으로)

## 순서
1. `git status` 로 바뀐 파일을 본다. **이번 작업과 상관없는 파일**이 있으면 사용자에게 묻는다
   ("이 파일도 같이 저장할까요?"). 비밀번호·키가 든 파일(`.env` 등)은 저장하지 않는다.
2. 기록을 고친다 (커밋에 같이 들어가게 **저장 전에**):
   - `FEATURES.md`: 새 기능 줄 추가 또는 상태·파일·확인 방법 갱신
   - `NOW.md`: "지금 작업" 을 비우거나 다음 단계 카드로 바꾸고, "다음에 할 일" 과 "마지막 저장" 을 고친다
   - `DECISIONS.md`: 이번에 중요한 결정을 했으면 한 줄 (예: "데이터는 브라우저에만 저장 -- 서버 없이 쓰려고")
   - `NAMES.md`: 새 이름을 썼으면 추가
3. 저장한다:
   ```
   git add <이번 작업 파일들> dev-notes/
   git commit -m "기능: 할 일 목록 - 입력과 목록"
   ```
   메시지는 한국어로 짧게, 앞에 종류를 붙인다: `기능:` 새 기능 · `수정:` 고침 · `모양:` 디자인 · `정리:` 기타 · `중간 저장:` 미완성 · `되돌리기:` 되돌림(light-undo)
4. 사용자에게 한 줄로 알린다: "저장했습니다: 기능: 할 일 목록 - 입력과 목록 (되돌아올 수 있는 지점)"

## 하지 않는 것
- 확인(light-check) 없이 "기능:" 으로 저장하기 -- 미완성이면 "중간 저장:" 으로 한다
- 인터넷 저장소에 올리기(push)나 배포를 묻지 않고 하기
- `git add -A` 로 무엇이 들어가는지 모른 채 저장하기
