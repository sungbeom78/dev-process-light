# light-save — 저장하기

## 언제 -- 단계마다 자주
| 단계가 끝남 | 저장 종류 | 예 |
|---|---|---|
| 작업 카드 합의 (`light-start`) | `중간 저장:` | `중간 저장: 할 일 목록 - 작업 카드 합의` |
| 만들기 한 덩어리 (30분 안쪽, 확인 전) | `중간 저장:` | `중간 저장: 할 일 목록 - 입력 칸까지` |
| 확인 끝 (`light-check`, 사용자 확인) | `기능:` `수정:` `모양:` `정리:` | `기능: 할 일 목록 - 입력과 목록` |
| 되돌림 (`light-undo`) | `되돌리기:` | |
| 하루 작업을 마칠 때 | `중간 저장:` | |

자주 저장할수록 되돌아올 수 있는 지점이 많아진다. 확인하지 않은 것은 `중간 저장:` 으로만 저장한다.

## 순서
1. `git status` 로 바뀐 파일을 본다. **이번 작업과 상관없는 파일**이 있으면 사용자에게 묻는다
   ("이 파일도 같이 저장할까요?"). 비밀번호·키가 든 파일(`.env` 등)은 저장하지 않는다.
2. 설명서: 카드의 `설명서:` 가 해당 없음이 아니면 `manual/` 이 이번 변경과 맞게 고쳐졌는지 본다.
   안 고쳐졌으면 저장하기 전에 `light-manual` 로 고친다. "해당 없음"이면 이유가 카드에 있는지 본다.
3. 기록을 고친다 (커밋에 같이 들어가게 **저장 전에**):
   - `FEATURES.md`: 새 기능 줄 추가 또는 상태·파일·확인 방법·설명서 갱신
   - `NOW.md`: "지금 작업" 을 비우거나 다음 단계 카드로 바꾸고, "다음에 할 일" 과 "마지막 저장" 을 고친다
   - `DECISIONS.md`: 이번에 중요한 결정을 했으면 한 줄 (예: "데이터는 브라우저에만 저장 -- 서버 없이 쓰려고")
   - `NAMES.md`: 새 이름을 썼으면 추가
   - `LOG.md`: 맨 위(설명 아래)에 한 줄 -- `- 2026-10-11 14:05 · 확인 · 할 일 목록 완료 기준 3개 · 통과 · AI`
     (단계: 준비·합의·만들기·확인·저장·되돌리기·문제·결정·배움, 누가: AI / 사용자). 비밀번호·키·개인정보는 적지 않는다.
4. 저장한다 (설명서도 같은 저장에):
   ```
   git add <이번 작업 파일들> dev-notes/ manual/
   git commit -m "기능: 할 일 목록 - 입력과 목록"
   ```
   메시지는 한국어로 짧게, 앞에 종류를 붙인다: `기능:` 새 기능 · `수정:` 고침 · `모양:` 디자인 · `정리:` 기타 · `중간 저장:` 미완성 · `되돌리기:` 되돌림(light-undo)
5. 인터넷 저장소에 올리기 -- `NOW.md` `## 설정` 의 `인터넷 저장소에 올리기(push):` 를 따른다.
   - `예` → `git push`. 실패하면 이유를 말하고(인터넷·로그인 등) 저장은 내 컴퓨터에 그대로 있다고 알린다.
   - `아니오` → 올리지 않는다.
   - `(아직 정하지 않음)` 이고 `git remote` 에 저장소가 있으면 **한 번만** 묻는다:
     "저장할 때마다 인터넷 저장소(<주소>)에도 올릴까요? 다른 컴퓨터에서도 이어서 할 수 있고, 저장소가 공개면 누구나 볼 수 있어요."
     답을 `## 설정` 과 `DECISIONS.md`(`[사용자]`, 답 그대로)에 적는다. 저장소가 없으면 묻지 않는다.
6. 기록 보기 페이지 -- `## 설정` 의 `기록 보기 페이지:` 가 경로면 `light-portal` 로 다시 만든다 (만들지 않음이면 건너뜀).
7. 사용자에게 한 줄로 알린다: "저장했습니다: 기능: 할 일 목록 - 입력과 목록 (되돌아올 수 있는 지점)" + 올렸으면 "· 인터넷 저장소에도 올림"
8. 설명서를 만들거나 고쳤으면 바로 이어서 **채팅에 그대로 보여 준다** (`light-manual` 의 "저장 후 채팅에 보여 주기").

## 하지 않는 것
- 확인(light-check) 없이 "기능:" 으로 저장하기 -- 미완성이면 "중간 저장:" 으로 한다
- 새 기능·사용법 변경인데 설명서 없이 "기능:" 으로 저장하기
- 인터넷 저장소에 올리기(push)를 한 번도 묻지 않고 하기, 배포(사이트 공개)를 묻지 않고 하기
- 작업 기록(LOG.md) 없이 저장하기
- `git add -A` 로 무엇이 들어가는지 모른 채 저장하기
