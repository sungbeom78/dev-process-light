# light-start — 시작하기 전에 합의

## 언제
- "○○ 기능 만들어 줘", "○○ 바꿔 줘" 같은 요청을 받았을 때 -- **코드를 쓰기 전에**
- 오타·문구·색 하나 바꾸기처럼 아주 작은 일은 생략하고 바로 해도 된다 (그래도 끝나면 light-check)

## 순서
1. `dev-notes/FEATURES.md` 를 본다. 이번 요청이
   - 새 기능인지, 기존 기능을 바꾸는지
   - 어떤 파일을 건드릴지, 그 파일을 **다른 기능도 쓰는지** ("함께 쓰는 파일" 포함)
   를 확인한다.
2. 요청이 크면 나눈다. 기준: **한 단계 = 30분 안에 만들고 확인할 수 있는 크기**, 단계마다 저장한다.
   예) "가계부" → ① 입력과 목록 ② 월별 합계 ③ 그래프
3. 작업 카드를 만들어 `dev-notes/NOW.md` 의 "지금 작업" 에 적고, 사용자에게 보여준다:
   ```
   ### 작업: 할 일 목록 (1/3 입력과 목록)
   - 목표: 할 일을 적고 체크할 수 있다
   - 완료 기준:
     - [ ] 할 일을 입력하고 Enter 를 누르면 목록에 추가된다
     - [ ] 체크하면 줄이 그어진다
     - [ ] 새로고침해도 목록이 남아 있다
   - 건드릴 기능: 할 일 (새 기능) -- 새 파일 todo.js, index.html 에 메뉴 1줄 추가
   - 영향 받을 수 있는 기능: 메모 (index.html 을 같이 씀) -- 끝나고 메모도 점검
   - 진행: 계획
   ```
   완료 기준은 **사람이 화면에서 직접 확인할 수 있는 문장**으로 쓴다 ("코드가 깔끔하다" 같은 것은 안 된다).
4. "이대로 진행할까요?" 라고 묻고, 사용자가 고치면 카드를 고친다. **확인받기 전에는 만들지 않는다.**
5. 새 이름이 필요하면 `dev-notes/NAMES.md` 를 보고, 없으면 카드와 함께 제안한다.
6. 확인받으면 진행을 "만드는 중" 으로 바꾸고 만든다.

## 만드는 동안
- 카드에 적은 파일만 고친다. 다른 기능의 파일을 고쳐야 할 것 같으면 **멈추고 먼저 말한다.**
- 사용자가 중간에 요청을 바꾸면 카드를 먼저 고치고 다시 확인받는다.
- 다 만들면 `light-check` 로 간다. "다 됐습니다" 라고 먼저 말하지 않는다.
