# 따라 하기 -- 나만의 홈페이지 (메모 → 할 일 → 가계부)

이 예시는 **실제로 수행한 기록**입니다. dev-process-light 를 설치한 빈 폴더에서 기능 3개를 차례로 붙이고,
중간에 생긴 문제와 되돌리기까지 그대로 남겼습니다.
결과 파일: [`site/`](site/index.html) · 사용설명서: [`manual/`](manual/index.html) · 기록: [`dev-notes/`](dev-notes/FEATURES.md) · 저장 목록: [`git-log.txt`](git-log.txt) ·
휴대폰 화면: [`screenshot-mobile.png`](screenshot-mobile.png)

`site/index.html` 을 브라우저로 열면 바로 써 볼 수 있습니다 (서버·설치 필요 없음).

---

## 0. 설치하고 시작
```bash
bash ~/dev-process-light/install.sh my-homepage
```
> **나:** light-resume 으로 시작해 줘
>
> **AI:** (처음인 프로젝트 → git 시작, `.gitignore` 만들기) 무엇을 만드는 사이트인가요?
>
> **나:** 혼자 쓰는 홈페이지. 메모, 할 일, 가계부.

AI가 `NOW.md` 에 프로젝트 설명과 할 일 3개를 적고, 결정 하나를 남긴 뒤 첫 저장을 합니다.
```
준비: 작업 기록 시작
```

## 1. 메모 -- 시작 전 합의 → 확인 → 저장
> **나:** 메모 기능 만들어 줘

AI는 바로 만들지 않고 작업 카드를 보여 줍니다 (`light-start`).
```
### 작업: 메모
- 목표: 메모를 적고 지울 수 있다
- 완료 기준:
  - [ ] 메모를 적고 Enter 를 누르면 목록 맨 위에 생긴다
  - [ ] × 를 누르면 지워진다
  - [ ] 새로고침해도 남아 있다
- 건드릴 기능: 메모 (새 기능) -- index.html, style.css, tabs.js, memo.js 새로 만듦
- 영향 받을 수 있는 기능: 없음 (첫 기능)
```
> **나:** 좋아.

만든 뒤 AI가 확인합니다 (`light-check`). 실제 브라우저로 열어 입력·새로고침을 해 봅니다.
```
✅ 문법 오류 없음 (node --check memo.js tabs.js)
✅ 메모를 쓰고 새로고침해도 남음 (브라우저에서 '우유 사기' 입력 → 새로고침 → 목록 확인)
✅ 휴대폰 폭에서 화면이 넘치지 않음 (375px 로 열어 가로 스크롤 없음 확인)
👀 직접 확인해 주세요: 글자 크기와 색이 마음에 드는지
```
저장하면서 기능 지도에 첫 줄이 생깁니다 (`light-save`).
```
| 메모 | ✅ 동작 | memo.js | 메모를 쓰고 새로고침해도 남아 있다 |
```

## 2. 할 일 -- "함께 쓰는 파일"을 건드리면 다른 기능도 점검
카드의 영향 항목:
```
- 건드릴 기능: 할 일 (새 기능) -- todo.js 새로 만듦, index.html 에 메뉴·화면 추가
- 영향 받을 수 있는 기능: 메모 (index.html 을 같이 씀) -- 끝나고 메모도 점검
```
확인 결과에 **메모가 같이 들어갑니다.**
```
✅ 할 일: 추가·체크 후 새로고침해도 남음 (입력 → 체크 → 새로고침)
✅ 메모: 예전에 쓴 메모가 그대로 (1단계에서 쓴 '우유 사기' 확인)
✅ 탭 전환: 메모·할 일 (각 탭을 눌러 화면 확인)
```

## 3. 가계부 -- 확인 단계가 문제를 잡은 장면 ⭐
AI는 가계부를 만들면서 저장 코드를 `store.js` 하나로 모으자고 제안했습니다.
메모·할 일 파일도 고치게 되므로 **카드에 먼저 적고 확인받았습니다** (규칙 3).
```
- 영향 받을 수 있는 기능: 메모·할 일 (저장 코드를 store.js 로 모음) -- 둘 다 점검
```
첫 번째로 만든 결과를 확인하자:
```
✅ 가계부: 2건 입력 → 새로고침 → 이번 달 합계 13,500원
❌ 메모: 예전에 쓴 메모가 사라짐
❌ 할 일: 예전 항목이 사라짐
```
**새 기능은 잘 됐지만, 예전에 쓴 메모와 할 일이 안 보였습니다.** `store.js` 가 저장 이름 앞에 `home:` 을 붙여서
예전 이름(`memo`, `todo`)으로 저장된 내용을 찾지 못한 것입니다.
새 기능만 확인했다면 AI는 "가계부 완료했습니다"라고 했을 것이고, 다음 날 메모가 전부 사라진 것을 발견했을 겁니다.

AI는 저장 이름을 원래대로 두도록 고치고, **모든 기능을 다시** 확인한 뒤 저장했습니다.
그리고 같은 실수를 반복하지 않도록 기록을 남겼습니다.
- `FEATURES.md` 함께 쓰는 파일: `store.js (저장 -- 저장 이름을 바꾸면 예전 데이터가 안 보임)`
- `NAMES.md`: `| 저장 이름 | memo / todo / budget | localStorage 키. 바꾸지 않는다 |`
- `DECISIONS.md`: 무엇을 발견했고 왜 그렇게 정했는지 한 줄

## 4. 되돌리기
> **나:** 색을 파란색으로 바꿔 줘
>
> (바꾸고 확인하고 저장: `모양: 기본 색을 파란색으로`)
>
> **나:** 음... 아까 색이 나았어. 되돌려 줘

AI는 저장 목록을 쉬운 말로 보여 주고, 무엇이 바뀌는지 말한 뒤 되돌립니다 (`light-undo`).
```
최근 저장
 1. (방금) 모양: 기본 색을 파란색으로      ← 이것만 취소합니다. 기능은 그대로입니다
 2. 기능: 가계부 - 입력과 이번 달 합계
 3. 기능: 할 일 목록
```
기록을 지우는 방식(`reset --hard`)이 아니라 "취소하는 저장"을 새로 만듭니다. 그래서 마음이 바뀌면 되돌리기도 되돌릴 수 있습니다.
되돌린 뒤 모든 기능을 다시 확인하고, 이유를 기록과 함께 한 번에 저장했습니다.

## 5. 사용설명서 처음 만들기 (0.2.0)
> 0.3.0 에서 설명서 형식이 HTML 슬라이드로 바뀌어, 아래 파일 이름은 현재(HTML) 기준입니다. 형식 변환은 7장.

dev-process-light 를 0.2.0 으로 다시 설치했습니다. 스킬만 새 버전으로 바뀌고 기록(`dev-notes/`)은 그대로입니다.
```
bash ~/dev-process-light/install.sh my-homepage     → 스킬 6개, [유지] dev-notes 4장, AGENTS.md 규칙 블록 갱신
```
> **나:** 지금 있는 기능으로 사용설명서 만들어 줘

AI가 기능 지도의 기능마다 장을 하나씩 만듭니다 (`light-manual`).
```
manual/index.html   목차: 표지 · 한눈에 · 시작하기(2쪽) · 기능 목록 · 바뀐 점
manual/memo.html    메모        (따라 하기 3단계 = 3쪽)
manual/todo.html    할 일       (따라 하기 4단계 = 4쪽)
manual/budget.html  가계부      (따라 하기 4단계 = 4쪽)
```
그리고 **설명서에 쓴 그대로 따라 해 봅니다.** 코드 이름이 아니라 화면에 보이는 글자로 눌러 봅니다
("[할 일] 버튼", "할 일을 적고 Enter 칸"). 처음 쓰는 사람처럼 빈 브라우저에서 합니다.
```
✅ 시작하기 2  [메모] [할 일] [가계부] 버튼이 보임
✅ 메모 2      Enter·[추가] 둘 다 → 맨 위에 생김
✅ 할 일 3     네모 칸 → 체크 + 줄
✅ 가계부 3    '2026-10 · 점심 9,000원' + 합계 9,000원
✅ 가계부 알아 두면  금액 0 은 들어가지 않음
... (11개 모두 ✅, 콘솔 오류 없음)
```
기능 지도에 `설명서` 칸을 더하고 저장한 뒤, 설명서를 **채팅에 그대로** 보여 줍니다.
```
정리: 사용설명서 처음 만듦 (메모·할 일·가계부)
```

## 6. 사용 방법이 바뀌면 설명서도 -- "체크한 할 일은 맨 아래로"
> **나:** 체크한 할 일은 목록 맨 아래로 내려가게 해 줘

작업 카드에 설명서 줄이 들어갑니다.
```
### 작업: 체크한 할 일은 맨 아래로
- 완료 기준:
  - [ ] 체크하면 그 일이 목록 맨 아래로 내려간다
  - [ ] 체크를 풀면 위쪽으로 올라간다
  - [ ] 새로고침해도 순서와 체크가 그대로다
- 건드릴 기능: 할 일 -- todo.js 만
- 영향 받을 수 있는 기능: 없음 (함께 쓰는 파일을 건드리지 않음)
- 설명서: 고침 (manual/todo.html 3단계 페이지, 바뀐 점)
```
확인 단계에서 바뀐 설명서를 다시 따라 하고, 다른 기능도 점검합니다.
```
✅ 할 일 3(바뀐 점)       체크한 일은 목록 맨 아래로
✅ 할 일 알아 두면(바뀐 점) 체크를 풀면 위쪽으로 올라감
✅ 메모·가계부 따라 하기 그대로, 탭 3개, 휴대폰 폭 넘침 없음
```
코드·설명서·기록이 **한 번에** 저장됩니다.
```
수정: 체크한 할 일은 목록 맨 아래로
  todo.js · manual/todo.html · manual/index.html · dev-notes/FEATURES.md · dev-notes/NOW.md
```
채팅에는 바뀐 부분만 그대로 보여 줍니다.
```
manual/todo.html -- 3단계 페이지
  3. 끝난 일 왼쪽의 네모 칸을 누릅니다. 체크 표시가 되고 글자에 줄이 그어지며, 목록 맨 아래로 내려갑니다.
manual/index.html -- 바뀐 점
  - 2026-10-08 할 일: 체크한 일은 목록 맨 아래로 내려갑니다 (할 일 3단계)
열기: manual/index.html (브라우저 · P = 발표 · N = 대본)
```
4번의 "파란색으로 바꾸기"처럼 **색만 바꾼 작업은 사용법이 같으므로 설명서는 해당 없음**입니다.

## 7. 설명서를 HTML 슬라이드로 (0.3.0)
설명서 규칙이 바뀌어(웹페이지 기본 + pptx 페이지 모양 + 그림 위주 + 페이지마다 대본) 4장을 다시 만들었습니다.

| 장 | 쪽 | 그림 |
|---|---|---|
| 목차 `index.html` | 6 | 기능 카드 · 시작하기 순서도 · 화면 흉내 · 바뀐 점 표 |
| 메모 `memo.html` | 6 | 한눈에 순서도 · 단계마다 화면(누르는 곳 강조) · 남는 것/사라지는 것 비교 |
| 할 일 `todo.html` | 7 | 체크 전/후 화면 나란히 (바뀐 사용법) |
| 가계부 `budget.html` | 7 | 이렇게/이렇게 말고 비교 · 고치는 순서도 |

확인: `manual_tool.py check` 통과(페이지마다 그림·대본, 단계 페이지, 링크), 실제 브라우저로 26쪽을 열어 넘침·깨짐 없음,
`manual_tool.py pptx` 로 26장 pptx(대본은 발표자 노트) 생성.

```
수정: 체크한 할 일은 목록 맨 아래로

정리: dev-process-light 0.2.0 으로 업데이트 (사용설명서 스킬 추가)
되돌리기: 모양: 기본 색을 파란색으로 -- 원래 색이 더 낫다
모양: 기본 색을 파란색으로
기능: 가계부 - 입력과 이번 달 합계 (저장 코드 store.js 로 정리)
기능: 할 일 목록
기능: 메모

```
저장 하나하나가 "되돌아올 수 있는 지점"입니다. 다음 날 `light-resume` 을 하면 AI가 이 목록과 `NOW.md` 를 읽고
"가계부 2단계: 지난달과 비교 -- 아직 정하지 않음" 부터 이어 갑니다.
"사용설명서 보여 줘"라고 하면 `manual/index.html` 목차를, "가계부 설명 보여 줘"라고 하면 그 장을 보여 줍니다.
