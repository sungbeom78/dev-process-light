# 따라 하기 -- 나만의 홈페이지 (메모 → 할 일 → 가계부)

이 예시는 **실제로 수행한 기록**입니다. dev-process-light 를 설치한 빈 폴더에서 기능 3개를 차례로 붙이고,
중간에 생긴 문제와 되돌리기까지 그대로 남겼습니다.
결과 파일: [`site/`](site/index.html) · 기록: [`dev-notes/`](dev-notes/FEATURES.md) · 저장 목록: [`git-log.txt`](git-log.txt) ·
휴대폰 화면: [`screenshot-mobile.png`](screenshot-mobile.png)

`site/index.html` 을 브라우저로 열면 바로 써 볼 수 있습니다 (서버·설치 필요 없음).

---

## 0. 설치하고 시작
```bash
bash ~/dev-process-light/install.sh my-homepage
```
> **나:** light-resume 으로 시작해 줘
>
> **AI:** (처음인 프로젝트 → git 시작, `.gitignore` 만들기) 무엇을 만드는 사이트인가요?
>
> **나:** 혼자 쓰는 홈페이지. 메모, 할 일, 가계부.

AI가 `NOW.md` 에 프로젝트 설명과 할 일 3개를 적고, 결정 하나를 남긴 뒤 첫 저장을 합니다.
```
준비: 작업 기록 시작
```

## 1. 메모 -- 시작 전 합의 → 확인 → 저장
> **나:** 메모 기능 만들어 줘

AI는 바로 만들지 않고 작업 카드를 보여 줍니다 (`light-start`).
```
### 작업: 메모
- 목표: 메모를 적고 지울 수 있다
- 완료 기준:
  - [ ] 메모를 적고 Enter 를 누르면 목록 맨 위에 생긴다
  - [ ] × 를 누르면 지워진다
  - [ ] 새로고침해도 남아 있다
- 건드릴 기능: 메모 (새 기능) -- index.html, style.css, tabs.js, memo.js 새로 만듦
- 영향 받을 수 있는 기능: 없음 (첫 기능)
```
> **나:** 좋아.

만든 뒤 AI가 확인합니다 (`light-check`). 실제 브라우저로 열어 입력·새로고침을 해 봅니다.
```
✅ 문법 오류 없음 (node --check memo.js tabs.js)
✅ 메모를 쓰고 새로고침해도 남음 (브라우저에서 '우유 사기' 입력 → 새로고침 → 목록 확인)
✅ 휴대폰 폭에서 화면이 넘치지 않음 (375px 로 열어 가로 스크롤 없음 확인)
👀 직접 확인해 주세요: 글자 크기와 색이 마음에 드는지
```
저장하면서 기능 지도에 첫 줄이 생깁니다 (`light-save`).
```
| 메모 | ✅ 동작 | memo.js | 메모를 쓰고 새로고침해도 남아 있다 |
```

## 2. 할 일 -- "함께 쓰는 파일"을 건드리면 다른 기능도 점검
카드의 영향 항목:
```
- 건드릴 기능: 할 일 (새 기능) -- todo.js 새로 만듦, index.html 에 메뉴·화면 추가
- 영향 받을 수 있는 기능: 메모 (index.html 을 같이 씀) -- 끝나고 메모도 점검
```
확인 결과에 **메모가 같이 들어갑니다.**
```
✅ 할 일: 추가·체크 후 새로고침해도 남음 (입력 → 체크 → 새로고침)
✅ 메모: 예전에 쓴 메모가 그대로 (1단계에서 쓴 '우유 사기' 확인)
✅ 탭 전환: 메모·할 일 (각 탭을 눌러 화면 확인)
```

## 3. 가계부 -- 확인 단계가 문제를 잡은 장면 ⭐
AI는 가계부를 만들면서 저장 코드를 `store.js` 하나로 모으자고 제안했습니다.
메모·할 일 파일도 고치게 되므로 **카드에 먼저 적고 확인받았습니다** (규칙 3).
```
- 영향 받을 수 있는 기능: 메모·할 일 (저장 코드를 store.js 로 모음) -- 둘 다 점검
```
첫 번째로 만든 결과를 확인하자:
```
✅ 가계부: 2건 입력 → 새로고침 → 이번 달 합계 13,500원
❌ 메모: 예전에 쓴 메모가 사라짐
❌ 할 일: 예전 항목이 사라짐
```
**새 기능은 잘 됐지만, 예전에 쓴 메모와 할 일이 안 보였습니다.** `store.js` 가 저장 이름 앞에 `home:` 을 붙여서
예전 이름(`memo`, `todo`)으로 저장된 내용을 찾지 못한 것입니다.
새 기능만 확인했다면 AI는 "가계부 완료했습니다"라고 했을 것이고, 다음 날 메모가 전부 사라진 것을 발견했을 겁니다.

AI는 저장 이름을 원래대로 두도록 고치고, **모든 기능을 다시** 확인한 뒤 저장했습니다.
그리고 같은 실수를 반복하지 않도록 기록을 남겼습니다.
- `FEATURES.md` 함께 쓰는 파일: `store.js (저장 -- 저장 이름을 바꾸면 예전 데이터가 안 보임)`
- `NAMES.md`: `| 저장 이름 | memo / todo / budget | localStorage 키. 바꾸지 않는다 |`
- `DECISIONS.md`: 무엇을 발견했고 왜 그렇게 정했는지 한 줄

## 4. 되돌리기
> **나:** 색을 파란색으로 바꿔 줘
>
> (바꾸고 확인하고 저장: `모양: 기본 색을 파란색으로`)
>
> **나:** 음... 아까 색이 나았어. 되돌려 줘

AI는 저장 목록을 쉬운 말로 보여 주고, 무엇이 바뀌는지 말한 뒤 되돌립니다 (`light-undo`).
```
최근 저장
 1. (방금) 모양: 기본 색을 파란색으로      ← 이것만 취소합니다. 기능은 그대로입니다
 2. 기능: 가계부 - 입력과 이번 달 합계
 3. 기능: 할 일 목록
```
기록을 지우는 방식(`reset --hard`)이 아니라 "취소하는 저장"을 새로 만듭니다. 그래서 마음이 바뀌면 되돌리기도 되돌릴 수 있습니다.
되돌린 뒤 모든 기능을 다시 확인하고, 이유를 기록과 함께 한 번에 저장했습니다.

## 최종 저장 목록
```
되돌리기: 모양: 기본 색을 파란색으로 -- 원래 색이 더 낫다
모양: 기본 색을 파란색으로
기능: 가계부 - 입력과 이번 달 합계 (저장 코드 store.js 로 정리)
기능: 할 일 목록
기능: 메모
준비: 작업 기록 시작
```
저장 하나하나가 "되돌아올 수 있는 지점"입니다. 다음 날 `light-resume` 을 하면 AI가 이 목록과 `NOW.md` 를 읽고
"가계부 2단계: 지난달과 비교 -- 아직 정하지 않음" 부터 이어 갑니다.
